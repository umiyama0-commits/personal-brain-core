# うみやまAI 利用フェーズ戦略

★ 2026-05-21 初版、海山 + Claude 共同 draft

うみやまAI を社員 200 人に正式リリースする前に、**何を期待していいか / 何は期待しちゃダメか** の境界をフェーズで明確化する。

## 命名 (★社員向け公式名称)

| 内部呼称 | 公式名称 (社員向け) | 概要 |
|---|---|---|
| **Phase 1** | **うみやまAI (v1)** | 質問応答 + 考え方アライン |
| **Phase 2** | (v2、名称未定) | AI agent としてタスク実行・伴走 |

→ 社員向けでは **「うみやまAI (v1)」「うみやまAI (v2)」** で統一。`Phase 1 / 2` は社内戦略・技術文書内のみ使用。

---

## 全体俯瞰

```
[ベータ期: 2026-04 〜 2026-05]
  ├─ 海山周辺 + 自然増の社員 20-30 名
  └─ 質問応答が主、修正希望ループで学習中
                  ↓
[うみやまAI (v1) = Phase 1: アライメント期] ★ 2026-05-21 正式公開済、以後稼働中
  ├─ 全社員 200 名に開放
  ├─ 業務質問への海山視点回答
  ├─ 会社の考え方 (VMV / 判断軸 / 戦略) のアライン
  └─ 期間目安: 3-6 ヶ月以上、reality 見て判断
                  ↓ (v1 が安定して、運用パターン見えたら)
[うみやまAI (v2) = Phase 2: エージェント期]
  ├─ 主要管理職 → 段階的に全社員に拡大
  ├─ AI agent としてツール統合・タスク実行
  ├─ 社内業務の伴走 (= 手を動かす AI)
  └─ 着手時期: ★「v1 の reality を見てから決める」(海山判断 2026-05-21)
```

## うみやまAI (v1) = Phase 1: アライメント期 (現在 - 6 ヶ月以上)

### 目的

1. **業務質問への即答**
   売上数字 / 組織情報 / VMV / 規定 / 業績ハイライト 等を社員が即取得できる
2. **海山の考え方の社内浸透**
   海山の判断軸 (= ROI 2 年 / Voice & Do / Customer Obsession 等) を、社員が **日常的に触れる** ことで内化する
3. **会社の「考え方」をアラインする**
   200 人それぞれが OWNDAYS の戦略・文化・トーンを同じ理解で動く土台になる

### 対象ユーザ

**全社員 200 名**。役職問わず。誰でも友達追加で開始。

### 主要機能 (= Phase 1 で使える機能)

| | 内容 |
|---|---|
| **質問応答 (Q&A)** | 業務 / 戦略 / 数字 / 悩み相談 |
| **個別メモリー** | 各社員との会話履歴・進行話題・好みのスタイルを蓄積、次回応答に反映 |
| **修正希望ループ** | 「違う」「正しくは…」で社員が訂正、海山がレビューして wiki 更新 |
| **添付ファイル解析** | PDF / Excel / Word / 画像を添付すると内容を読んで応答 |
| **URL 取り込み** | メッセージ内 URL を自動 fetch して内容に基づく応答 |
| **過去履歴の参照** | 「先週話した件の続き」型の文脈継続 |

### Phase 1 で **やらないこと** (= 期待しちゃダメな線引き)

| やらないこと | 理由 |
|---|---|
| ❌ メール / 議事録 / 提案書を **作成する** | Phase 2 領域、Phase 1 では「考え方の提示」まで |
| ❌ Drive / Slack / メールに **書き込む** | 実行アクションは Phase 2 |
| ❌ 部下の **評価 / 処遇** を決める | 海山本人が判断する領域 |
| ❌ 取引先 / 顧客と **直接やりとり** する | 対外責任が伴う、Phase 2 でも慎重 |
| ❌ 自動で **会議招集 / 予定設定** する | Phase 2 領域 |
| ❌ **未公開案件 (M&A / 重大人事)** に踏み込む | 機密境界、Phase 2 でも対象外 |

### Phase 1 の成功指標 (= これ達成したら Phase 2 検討入る)

| 指標 | 目標 | 計測方法 |
|---|---|---|
| **継続利用率 (DAU/MAU)** | 50%+ | bot_events.jsonl で 7 日 / 30 日 active 比 |
| **修正希望の質的減少** | 月次で hallucination contradicted < 2 件 | clone_hallucination_check の結果 |
| **応答スタイル評価** | 第三者 blind 採点で overall 4.0+/5.0 | clone_external_eval の月次 report |
| **海山判断軸の社員理解度** | アラインメント満足度調査で 70%+ | 四半期 1 回の社員アンケート |
| **平均会話深度** | 1 セッション 3 ターン+ | clone_history 分析 |
| **「業務に役立った」感じる社員比率** | 60%+ | 半年に 1 回の調査 |

### Phase 1 の制約・注意

- **応答は参考意見、最終判断は社員自身** (= 法的責任は海山にあるが、業務判断は社員)
- **専門領域 (医療 / 法律 / 深刻メンタル)** は専門家相談を勧める
- **間違えることもある** ことを前提に使う

### Phase 1 期間の運用責任

| 役割 | 担当 | 頻度 |
|---|---|---|
| **応答品質モニター** | 海山 (自動レポート見る) | 週次 |
| **修正希望レビュー** | 海山 (mini digest 経由) | 毎日 15:00 |
| **会話発見レビュー** | 海山 (mini digest 経由) | 毎日 16:00 |
| **wiki 更新** | 海山 (deliberate 編集) | 必要に応じて |
| **障害対応** | 海山 (LINE Push アラート → docker compose 操作) | 障害時 |

### Phase 1 のリスクと緩和

| リスク | 確率 | 緩和 |
|---|---|---|
| 「海山が言ってた」を根拠に社員が誤判断 | 中 | system prompt + welcome で「参考意見、最終判断は自分」明示 |
| 海山の判断軸 (社内戦略含) が社外に漏れる | 低 | clone_visibility public/private、wiki scrub、welcome で「DM 内容は社外共有しない」明記 |
| ハルシネーション (作り話) で重要数字が誤って伝わる | 中 | post-hoc fact verifier 03:45 daily、contradicted ≥ 3 で海山 Push |
| 海山が触らない時期に質が drift | 中 | drift_detector + auto_improve + style regression、月次 alignment_snapshot |
| 利用が一過性で 3 ヶ月後に DAU 急落 | 中-高 | 月次 metrics でモニター、低下したら原因分析 |

## うみやまAI (v2) = Phase 2: エージェント期 (v1 安定後、時期は v1 reality 次第)

### 目的

1. **AI agent として社員業務をアシスト・伴走**
   手を動かす AI、タスクを実行できる AI
2. **属人化した業務の標準化・効率化**
   「○○さんに頼まないと出来ない」を AI agent で代替可能に
3. **意思決定の補助 (高度版)**
   データ収集 → 分析 → 選択肢提示 → 推奨 → (社員承認) → 実行 のサイクル

### 対象ユーザ (段階的拡大)

```
1. 海山周辺 (= 役員、執行役員、AM/SV) 5-10 名
2. 主要管理職 (= 各本部長、リーダークラス) 20-30 名
3. 一般管理職 (= 課長 / 店長クラス) 100 名+
4. 全社員 200 名+
```

各段階で「**信頼性 + 安全性が confirmed**」してから次に進む。1 段階 = 2-3 ヶ月目安。

### 主要機能 (= Phase 2 で追加される機能)

| | 内容 | 必要技術 |
|---|---|---|
| **ツール呼び出し** | LINE Works / Drive / Slack / Calendar / 売上 API / Plaud / etc. を AI が呼ぶ | Anthropic tool use, function calling |
| **タスク実行** | 「議事録 draft 作って」「○○AM の月次レポート出して」型 | Agent orchestration (Claude Agent SDK or LangGraph) |
| **複数 turn の自律行動** | 1 リクエストで複数ステップ実行 (= データ取得 → 分析 → 整形 → 送信) | Agent loop + checkpointing |
| **実行前確認** | 重要アクション (= 書き込み / 外部送信) は AI が「これでいい?」と聞く | Human-in-the-loop pattern |
| **監査ログ + ロールバック** | 実行内容を全記録、必要なら巻き戻し | Audit log + reverse operation |
| **権限管理** | ユーザ別に「読み取り」「書き込み」「外部送信」の許可レベル設定 | Role-based access control |
| **業務 workflow 自動化** | 定期タスクを cron 化 (= 「毎週金曜に Board 用 summary 自動生成」) | scheduled task system |

### Phase 2 で **やらないこと** (= 永続的に AI に任せない)

| やらないこと | 理由 |
|---|---|
| ❌ 取引先 / 顧客への **直接対外送信** (メール / 契約書) | 法的責任、信頼関係 |
| ❌ **採用決定 / 解雇 / 評価** の最終判断 | 人事責任は人が負う |
| ❌ 重大経営判断 (M&A / 戦略変更 / 重要投資) | 海山本人の責任領域 |
| ❌ 海山の **個人名で発信** する SNS / メディア | 個人発信は本人のみ |
| ❌ **未承認の対外アクション** | 安全機構が破られた時の影響大 |

### Phase 2 のユースケース例

#### A. データ集計・レポート系 (低リスク、最初に着手)

- 「来週の経営会議用に過去 4 週の売上トレンド資料 draft」
- 「○○AM 管轄店の月次サマリ + 前年比を Excel で」
- 「FY27 5 月の進捗を Slack の経営チャネルに投稿する文章を作って」 (= 投稿は人が confirm)

#### B. 議事録・文書生成 (中リスク、要確認)

- 「先週の Plaud 録音から議事録 draft 作成」(既存パイプラインあり)
- 「店長 1on1 メモから learnings をクラスタリングして要約」
- 「VMV を反映した新人向け welcome 資料の draft」

#### C. 業務 workflow 自動化 (高頻度、価値高)

- 毎週月曜「Monday Dash 取り込み → 重要 highlights を slack に投稿」
- 毎月「店舗別 TSA トレンドを担当 SV にメール (= 確認した上で送信)」
- 毎四半期「Board 用 summary 自動生成 → 海山確認 → 取締役会への配信準備」

#### D. リサーチ・分析支援 (要確認多い)

- 「JINS / Zoff の直近 3 ヶ月の動きをまとめて」 (= web 検索 + 集計)
- 「新店候補 5 物件の比較表」 (= 過去物件データ + 評価軸 + 推奨)
- 「店長候補 5 名の評価軸別 score 比較」

#### E. 個人秘書系 (海山周辺のみ、最終 Phase)

- 「明日の予定空き時間に新店開発のルート提案」
- 「来週のメール返信が必要なやつをまとめて (= 海山が承認したものだけ返信)」

### Phase 2 の成功指標

| 指標 | 目標 |
|---|---|
| **タスク成功率** | 95%+ (= AI が実行したタスクが意図通り) |
| **実行前確認の rejection rate** | 5-15% (低すぎる = 確認甘い、高すぎる = AI が暴走しがち) |
| **業務時間削減** | ユーザあたり月 5-10 時間 |
| **ヒヤリハット件数** | 月 0-2 件 (= 実行されたが「これは違った」が出る件数) |
| **権限違反 incident** | 0 件 (= 許可されてないツール / アクションを実行) |

### Phase 2 の技術的前提 (= まだ実装されてない)

★2026-07-03 追記: 下表のうち **Tool use 機構 / Agent orchestration** は admin 限定の analyst / consultant agent (`scripts/analyst/agent.py` + `scripts/consultant/agent.py`、★2026-06-20、LiteLLM tool-use) で実装済。ただし社員向け clone への統合は未着手 (= Phase 2 としては依然未達)。

現状の Personal Brain は **質問応答に特化** してる。Phase 2 開始には以下が必要:

| | 現状 | Phase 2 で必要 |
|---|---|---|
| **Tool use 機構** | ❌ | Anthropic / OpenAI の function calling 統合 |
| **Agent orchestration** | ❌ | Claude Agent SDK or LangGraph の導入 |
| **権限管理 (RBAC)** | ❌ | ユーザ別のツール許可リスト |
| **実行前確認 UX** | 部分 | Quick Reply で承認 / 拒否、明確な UI |
| **監査ログ** | bot_events.jsonl のみ | アクション実行ログ + 可逆性管理 |
| **scheduled tasks** | cron のみ | 個人別 / ユーザリクエスト由来の scheduled task |
| **API 統合** | 部分 (LINE Works / Drive 等) | Slack / Gmail / Calendar / 売上 API 全部 |

Phase 2 着手の **実装期間**: 3-6 ヶ月、~200-400 時間想定。

### Phase 2 のリスクと緩和

| リスク | 緩和 |
|---|---|
| 誤った実行で業務 / 顧客に影響 | 全実行を **実行前確認 + 監査ログ**、書き込み系は段階的開放 |
| 権限超過 (許可されてないアクション) | RBAC 厳格化、tool 別に許可 user list |
| AI が暴走して連続呼び出し | rate limit + max steps cap |
| 重要意思決定が「AI に任せられた」化 | 人事 / 経営 / 対外系は永続的に対象外、welcome / docs で明示 |
| ハルシネーション → 誤実行 | 実行前の事実確認 step を必須化 (= grounding 強制) |

## v1 → v2 の移行条件 (= いつ v2 始めるか)

★ 2026-05-21 海山判断: **「v1 の reality を見てから決める」**。
時期は事前に固定しない、v1 が以下の条件を満たした時点で検討開始。

以下が **全部** 揃った時に v2 着手判断:

- [ ] v1 が 3 ヶ月以上連続で安定 (= ハルシネーション contradicted 月 < 2 件)
- [ ] 全社員の継続利用率 50%+ が 1 ヶ月以上維持
- [ ] 第三者 blind 採点で overall 4.0+/5.0 が 2 回連続
- [ ] 海山が「v2 に行きたい / 行ける」と判断 (= 本人の覚悟)
- [ ] v2 着手の技術前提 (上記 7 個) のうち最低 4 個が実装済

これらの条件未達なら **v1 を継続深化**。焦らない。

「v1 reality を見てから」の意味:
- 半年経って利用が継続してれば → v2 検討入る価値あり
- 半年経って継続率落ちてれば → v1 を深掘り、v2 は延期 or キャンセル
- 「v1 で十分」 という結論もあり得る (= overengineering 回避)
